# Система обробки замовлень

Потрібен JDK 27. В IntelliJ IDEA виберіть JDK 27 для Project SDK і Gradle JVM.
Натисніть **Reload All Gradle Projects**, відкрийте `Main.java` та натисніть ▶ біля `main`.

Або запустіть у терміналі:

```powershell
.\gradlew.bat run
```

## Як працює програма

1. `Main` створює товари через JavaFaker та Lombok `@Builder`.
2. Товари потрапляють у замовлення `Order<T extends Product>`.
3. `OrderExecutor` передає замовлення чотирьом потокам.
4. `OrderProcessor` обробляє замовлення і зберігає їх через `OrderStore`.
5. Повторне замовлення викликає виняток; решта продовжує оброблятися.

Очікуваний підсумок: `Збережено: 10, помилок: 1`.
Одна помилка навмисна: програма двічі передає те саме замовлення.
Порядок рядків може відрізнятися через паралельну роботу потоків.

## Де виконано вимоги

| Вимога | Де дивитися |
| --- | --- |
| Узагальнення та обмеження `extends Product` | `Order`, `OrderProcessor`, `OrderStore`, метод `OrderExecutor.process` |
| Товари електроніки й одягу | `Electronics`, `Clothing` успадковують `Product` |
| Lombok `@Builder` | Конструктори `Electronics` і `Clothing` |
| JavaFaker | Створення назв, цін, кількості та характеристик у `Main` |
| Лямбди | Фільтр одягу в `Main` і задача потоку в `OrderExecutor` |
| Посилання на метод | `processor::process` у `Main` |
| Обробка винятків | `OrderProcessingException`, `try/catch` в обробнику й задачі потоку |
| Багатопоточність | `Executors.newFixedThreadPool` в `OrderExecutor` |
| Зберігання та синхронізація | `ConcurrentHashMap` у `ConcurrentOrderStore` |
| Модулі й контроль доступу | Файли `module-info.java`, пакет `storage.internal` не експортується |

## Модулі

- `order.model` — товари та замовлення.
- `order.storage` — зберігання замовлень.
- `order.processing` — обробка замовлень.
- `order.threading` — керування потоками.
- `order.app` — запуск програми.

`requires` підключає модуль, `exports` відкриває пакет іншим модулям.
`requires transitive` робить типи публічного API доступними також клієнтам модуля.
Реалізація сховища прихована в пакеті `org.example.storage.internal`.

## Коротко про допоміжні типи

- `record Order` — короткий запис класу з полями, конструктором і методами читання.
- `UUID` — унікальний ідентифікатор замовлення.
- `BigDecimal` — точне представлення ціни.
- `Consumer<Order<T>>` — обробник, який приймає замовлення.
- `try-with-resources` закриває пул і чекає завершення задач.
- `putIfAbsent` додає замовлення лише тоді, коли його ідентифікатора ще немає.

Сховище працює в пам’яті: після завершення програми дані зникають.
Lombok 1.18.48 потрібен для JDK 27. Плагін Gradle додає модульні назви залежностям JavaFaker,
щоб звичайний запуск і кнопка Run працювали без ручного налаштування модульного шляху.

Перевірка збирання й тестів:

```powershell
.\gradlew.bat build
```
